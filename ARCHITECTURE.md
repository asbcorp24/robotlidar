# Архитектура RobotLidar (обзор исходников)

> Актуализировано: 2026-11-12. Источник истины для конкретного поведения — код ветки `main` и конфигурация установленного устройства. Документация аппаратной части содержит исторические разделы; перед подключением проверяйте текущую прошивку и измерения.

## Контуры системы

1. **Raspberry Pi 4 / ROS 2 Jazzy** — навигация, SLAM, локализация, GPS, IMU, маршруты, зарядка, локальная веб-панель.
2. **ESP32-WROOM-32** — исполнительные механизмы гусениц, RC-приёмник, Hall, аварийная цепь, watchdog, дополнительные механизмы. Связь с Raspberry Pi — USB Serial 115200.
3. **Локальная веб-панель** — FastAPI на Raspberry Pi, обычно порт 8080; команды движения через ROS `/cmd_vel`, диагностика через WebSocket.
4. **Центральный сервер** — отдельное приложение Go в `radxa_zero3e/server/`: HTTP API, SQLite, учётные записи, привязка устройств, SRT/RTP ingest, WebRTC, удалённое управление.
5. **Видеоустройства и эмуляторы** — `orange_pi_zero_camera/`, `radxa_zero3e/device/`, `radxa_zero3e/orange_pi_pc_ipcam/`, `tools/rtsp_camera_emulator_windows/`.

## Управление движением

```text
Локальный браузер -> FastAPI -> ROS /cmd_vel
                                     |
Центральный Go сервер -> исходящий WebSocket Raspberry Pi
                                     |
                            remote_control_gateway
                                     |
                                ROS /cmd_vel
                                     |
                           esp32_track_bridge_node
                                     |
                            USB Serial 115200
                                     |
                     ESP32 -> гусеницы / RC / ESTOP
```

На Raspberry Pi мост `robotlidar/esp32_track_bridge_node.py` подписывается на `/cmd_vel`, `/actuator/command`, `/brush/command`, `/aux_motor/command`; публикует состояние приводов и датчиков, предоставляет сервисы `/drive/arm`, `/drive/estop`, `/drive/reconnect`. Параметры, включая `dry_run`, `auto_arm`, порт и таймауты, проверяйте в `config/esp32_drive.yaml` и в runtime.

ESP32 имеет независимую логику RC/SAFE/ROS и аппаратную аварийную цепь. **Программный STOP не заменяет физическую кнопку и разрыв силового контактора.** Не допускайте обхода межблокировок при изменениях в веб-панели, ROS или прошивке.

## Запуск и жизненный цикл

- `launch/web_stack.launch.py` поднимает постоянные ESP32 bridge/odometry, GPS, датчики, состояние позиции, менеджер зарядки и веб-панель. ESP32 и GPS в подключаемом `tractor_sensors.launch.py` отключаются, чтобы не дублировать узлы.
- `launch/mapping.launch.py` отвечает за картографирование.
- `launch/navigation.launch.py` подключает Nav2, сохранённую карту, bootstrap локализации и воспроизведение маршрута.
- `setup.py` задаёт консольные ROS entry points; веб-исполняемый файл `robotlidar_web` ссылается на `robotlidar.web_entry_camera:main`.
- `scripts/install_web_service.sh` и `systemd/robotlidar-web.service.template` обеспечивают автозапуск.

При диагностике проверяйте, какой стек уже запущен: отдельный запуск навигации/картографирования с датчиками может привести к дублированию узлов, если не настроены параметры `external_esp32_drive` и `start_gps`.

## Видео и удалённый доступ

Основной описанный в `radxa_zero3e/server/README.md` путь видео: IP-камера RTSP/TCP -> Raspberry Pi FFmpeg remux H.264 без перекодирования -> MPEG-TS/SRT -> Go-сервер -> WebRTC -> браузер. Для старых устройств сохранён RTP ingest.

`robotlidar/remote_control_gateway.py` открывает исходящий WebSocket на центральный сервер; предусмотрен также локальный/резервный UDP транспорт. Система должна прекращать движение при потере heartbeat.

## Авторизация и границы доверия

- **Локальная панель Raspberry Pi:** согласно `WEB.md`, авторизации нет. Не публикуйте порт 8080 в интернет; используйте изолированную доверенную сеть.
- **Центральный Go-сервер:** `radxa_zero3e/server/auth.go` реализует пользователей, хеширование паролей, сессии и привязку устройств через SQLite. В `main.go` саморегистрация отключена: учётные записи создаёт администратор.
- **Device ID не равен паролю.** При работе над удалённым управлением отдельно проверяйте проверку полномочий для HTTP/WebSocket и владение устройством.

## Известные расхождения документации

- В корневом `README.md` встречается старое назначение GPIO18/19 для Low Brake. В документации прошивки явно указано, что **с v1.9.6 отдельные тормозные сигналы удалены**, GPIO18/19 свободны. При переключении направления газ сбрасывается, выдерживаются паузы, затем плавно повышается.
- В старых таблицах RC встречается CH6 как ARM, тогда как более новые разделы описывают CH3 для актуатора и CH8 через SBUS для M4. **Не используйте старые таблицы как монтажную инструкцию.** Сверяйте конкретную версию прошивки и фактическую распиновку.
- Наименования MPU6050/MPU6500 в документах различаются; фактический драйвер называется `mpu6050_node.py`. Уточняйте установленную микросхему.

## Перед выпуском

1. Проверить версию прошивки, распиновку, напряжения, RC/SAFE/ROS и аппаратный ESTOP на стенде без нагрузки.
2. Проверить отсутствие дублированных ROS узлов, корректность `/cmd_vel` и таймаутов.
3. Проверить потерю сети/Serial/heartbeat и безопасную остановку.
4. Проверить права пользователя на устройство в центральном API и защищённый транспорт при внешнем доступе.
5. Зафиксировать результаты испытаний; этот обзор **не является** подтверждением аппаратной работоспособности.
