# ESP32-WROOM 30 pin — управление двумя гусеницами

PlatformIO/Arduino-прошивка для единого промежуточного контроллера между:

- пультом **Microzone MC7** и приёмником **MC8RE-V2**;
- Raspberry Pi 4 с ROS 2/Nav2;
- двумя силовыми BLDC-контроллерами левой и правой гусеницы;
- датчиками Холла двигателей;
- аппаратной аварийной цепью.

ESP32 является единственной точкой, которая формирует сигналы газа, тормоза, реверса и разрешения обоих силовых контроллеров. Пульт работает даже без Raspberry Pi. Raspberry Pi получает телеметрию и может управлять машиной только после явного переключения пульта в режим ROS.

---

## 1. Общая структура системы

```text
                         ПУЛЬТ MICROZONE MC7
                                  |
                               2,4 ГГц
                                  |
                         ПРИЁМНИК MC8RE-V2
                    CH1 / CH2 / CH5 / CH6 PWM
                                  |
                                  v
+--------------------- ESP32-WROOM-32 30 pin ----------------------+
|                                                                  |
|  CH1/CH2 -> команды гусениц                                      |
|  CH5     -> RC / SAFE / ROS                                      |
|  CH6     -> ARM                                                   |
|                                                                  |
|  USB Serial <------------------------------> Raspberry Pi 4       |
|                                                                  |
|  DAC GPIO25 -> газ LEFT        Hall LEFT  -> GPIO34               |
|  DAC GPIO26 -> газ RIGHT       Hall RIGHT -> GPIO35               |
|  GPIO16/17  -> реверс                                            |
|  GPIO18/19  -> тормоз                                             |
|  GPIO21/22  -> разрешение контроллеров                            |
|  GPIO32     -> аварийная петля                                    |
+------------------------------------------------------------------+
             |                                      |
             v                                      v
     BLDC-контроллер LEFT                    BLDC-контроллер RIGHT
             |                                      |
      мотор/гусеница LEFT                    мотор/гусеница RIGHT
```

---

## 2. Основные правила безопасности

1. **Нельзя подавать на GPIO ESP32 напряжение выше 3,3 В.**
2. Нельзя подавать на ESP32 напряжение аккумулятора 48–84 В.
3. Hall-сигналы двигателя 5 В подключаются только через согласование 5 → 3,3 В.
4. Входы `Low brake`, `Reverse`, `Ignition/Lock` подключаются через оптопары, реле или транзисторные интерфейсы.
5. Тонкий провод включения контроллера может иметь напряжение аккумулятора.
6. Аварийная кнопка должна не только подавать сигнал на GPIO32, но и аппаратно отключать силовой контактор.
7. Первый запуск выполнять только с вывешенными гусеницами.
8. Не подключать силовые контроллеры, пока не проверены все низковольтные сигналы мультиметром.
9. Цвета проводов китайских контроллеров не считаются гарантированной распиновкой.
10. Перед включением каждого неизвестного провода измерить его напряжение относительно сигнальной земли.

## 3. Используемая плата ESP32

Проект рассчитан на обычную плату:

```text
ESP32 DevKit V1
ESP32-WROOM-32
30 pin
```

Связь с Raspberry Pi выполняется через USB-разъём платы ESP32. Выводы UART0 `GPIO1/TX0` и `GPIO3/RX0` дополнительно не подключаются.

Если используется ESP32-WROVER с PSRAM, необходимо проверить, не заняты ли GPIO16 и GPIO17 внешней памятью. Для обычной ESP32-WROOM-32 эти выводы доступны.

| 14 | IN | MC8RE CH6 | Переключатель разрешения ARM |

| 34 | IN ONLY | Hall/Speed левой гусеницы | Один Hall-канал левого двигателя через 5 → 3,3 В |
| 35 | IN ONLY | Hall/Speed правой гусеницы | Один Hall-канал правого двигателя через 5 → 3,3 В |
| 2 | OUT | Светодиод состояния | Обычно встроенный LED платы ESP32 |
| GND | — | Общая сигнальная земля | ESP32, MC8RE, аналоговые интерфейсы |
| VIN/5V | POWER | Питание ESP32 | Стабилизированные 5 В либо USB |

### 4.2. Особенности GPIO34 и GPIO35

GPIO34 и GPIO35:

- работают только как входы;
- не имеют внутренних подтягивающих резисторов;
- подходят для Hall/Speed импульсов;
- не допускают 5 В.

Внешняя схема должна формировать уверенные уровни 0 и 3,3 В.

### 4.3. Выводы, которые лучше не использовать

| GPIO | Причина |
|---:|---|
| 6–11 | Подключены к Flash-памяти модуля |
| 1, 3 | USB-UART, прошивка и журнал Serial |
| 0 | BOOT, перевод в режим прошивки |
| 12 | Загрузочный strapping-вывод, чувствителен к уровню при старте |
| 2 | Также strapping-вывод; в проекте используется только встроенный LED |

### 4.4. Свободные выводы

После подключения всей системы обычно остаются:

```text
GPIO4
GPIO5
GPIO15
GPIO23
GPIO36 (только вход)
GPIO39 (только вход)
```

GPIO5 и GPIO15 являются загрузочными выводами, поэтому внешняя схема не должна жёстко удерживать на них неправильный уровень при включении.

## 5. Питание системы

### 5.1. Рекомендуемая схема питания

```text
АКБ 48–84 В
   |
   +-- главный предохранитель
   |
   +-- аварийный силовой контактор
   |      |
   |      +-- предохранитель LEFT  -> контроллер LEFT
   |      +-- предохранитель RIGHT -> контроллер RIGHT
   |
   +-- DC/DC 5 В для электроники
          |
          +-- Raspberry Pi 4
          +-- ESP32
          +-- MC8RE-V2
          +-- интерфейсная плата
```

Для Raspberry Pi лучше применять отдельный качественный DC/DC 5 В с достаточным током. Силовые и сигнальные провода прокладывать раздельно.

### 5.2. Питание MC8RE-V2

Приёмник питается стабилизированными 5 В через обычную трёхконтактную колодку любого канала:

```text
MC8RE +   -> +5 В BEC/DC-DC
MC8RE -   -> GND
MC8RE S   -> PWM-сигнал канала
```

Разъём `Ext Voltage` не использовать как основной вход питания приёмника — это вход измерения внешнего напряжения.

### 5.3. Питание ESP32

Для стенда:

```text
USB Raspberry Pi/ПК -> ESP32
```

Для постоянной установки:

```text
стабилизированные 5 В -> VIN/5V ESP32
GND                    -> GND ESP32
```

При одновременном внешнем питании ESP32 и подключённом USB необходимо учитывать схему конкретной DevKit-платы, чтобы избежать обратного питания USB. Безопасный вариант — оставить питание от USB либо использовать USB-кабель без линии +5 В, сохранив D+, D− и GND.

## 6. Подключение пульта Microzone MC7 и приёмника MC8RE-V2

### 6.1. Настройка MC7

Для ручного управления использовать режим катера:

```text
Model type: BOAT
Mixer: CH1/CH2 MIX
Speed Lock: OFF
```

При таком режиме пульт уже рассчитывает команды двух двигателей:

```text
CH1 -> левая гусеница
CH2 -> правая гусеница
```

ESP32 не выполняет смешивание повторно.

В прошивке должно быть:

```cpp
constexpr bool RC_PREMIXED_BY_TRANSMITTER = true;
```

Если микширование на пульте выключено, установить `false`, и ESP32 будет сама смешивать руление и газ.

### 6.2. Ожидаемая работа CH1 и CH2

```text
нейтраль:         CH1 ~= 1500 мкс, CH2 ~= 1500 мкс
вперёд:           CH1 > 1500,      CH2 > 1500
назад:            CH1 < 1500,      CH2 < 1500
поворот вправо:   CH1 > 1500,      CH2 < 1500
поворот влево:    CH1 < 1500,      CH2 > 1500
```

Фактические направления могут быть зеркальными. Исправлять через настройки пульта или параметры:

```cpp
constexpr bool RC_LEFT_REVERSED = false;
constexpr bool RC_RIGHT_REVERSED = false;
```

### 6.3. Подключение PWM-каналов

```text
MC8RE CH1 S ---- 1 кОм ---- GPIO27  ESP32
MC8RE CH2 S ---- 1 кОм ---- GPIO33  ESP32
MC8RE CH5 S ---- 1 кОм ---- GPIO13  ESP32
MC8RE CH6 S ---- 1 кОм ---- GPIO14  ESP32
MC8RE GND ----------------- GND     ESP32
```

Рекомендуемые подтяжки:

```text
GPIO27 ---- 47–100 кОм ---- GND
GPIO33 ---- 47–100 кОм ---- GND
GPIO13 ---- 47–100 кОм ---- GND
GPIO14 ---- 47–100 кОм ---- GND
```

PWM-выходы MC8RE имеют логический уровень около 3,3 В, поэтому делитель 5 → 3,3 В на этих четырёх входах не требуется. Последовательный резистор 1 кОм защищает вход при ошибке монтажа.

### 6.4. Назначение каналов управления

| Канал MC8RE | Назначение | Значение |
|---|---|---|
| CH1 | Левая гусеница | 1000–2000 мкс |
| CH2 | Правая гусеница | 1000–2000 мкс |
| CH5 | Выбор режима | около 1000 RC; 1500 SAFE; 2000 ROS |
| CH6 | Разрешение движения | около 1000 OFF; 2000 ON |

### 6.5. Режимы работы

```text
CH5 около 1000 мкс -> RC
    управление только пультом

CH5 около 1500 мкс -> SAFE
    газ 0
    тормоз включён
    контроллеры запрещены

CH5 около 2000 мкс -> ROS
    команды принимает Raspberry Pi
    пульт продолжает выполнять роль физического разрешения
```

После включения питания или переключения режима обязательно выполнить:

```text
ARM OFF -> ARM ON
```

ESP32 не разрешит привод, если включение произошло при уже поднятом переключателе ARM.

### 6.6. Настройка failsafe MC7/MC8RE

Обязательно настроить:

```text
CH1       -> 1500 мкс
CH2       -> 1500 мкс
CH5 MODE  -> 1500 мкс, SAFE
CH6 ARM   -> 1000 мкс, OFF
```

При потере радиосвязи ARM не должен оставаться включённым.

## 7. Подключение силовых контроллеров

На показанном контроллере присутствуют разъёмы с маркировкой:

```text
Hall
Low brake
Turn handle
Three speed
Burglar alarm
```

Для проекта используются `Hall`, `Low brake`, `Turn handle` и, после проверки, `Reverse`/`Ignition`.

`Three speed` и `Burglar alarm` на первом этапе оставить отключёнными.

### 7.1. Нельзя полагаться только на цвет провода

Перед подключением определить мультиметром:

- сигнальную землю;
- +5 В ручки газа;
- сигнальный вход ручки газа;
- вход Low brake;
- вход Reverse;
- провод Lock/Ignition;
- Hall +5 В, GND, A, B, C.

## 8. Аналоговый газ двух контроллеров

### 8.1. Разъём Turn handle

Обычно имеет три линии:

```text
+5 В от контроллера
GND контроллера
Signal 1–4,2 В
```

К ESP32 подключается только `Signal` и сигнальная земля. Провод +5 В ручки газа к ESP32 не подключать.

### 8.2. Выходы ESP32

```text
GPIO25 -> газ LEFT
GPIO26 -> газ RIGHT
```

Встроенный DAC ESP32 выдаёт приблизительно 0–3,3 В. Текущие безопасные настройки прошивки:

```cpp
constexpr uint8_t DAC_DISARMED = 0;
constexpr uint8_t DAC_IDLE = 77;       // около 1,00 В
constexpr uint8_t DAC_MAX_TEST = 220;  // около 2,85 В
```

Полного диапазона 4,2 В встроенный DAC не обеспечивает. Для окончательной схемы нужен двухканальный аналоговый усилитель.

### 8.3. Рекомендуемый интерфейс газа

```text
GPIO25 DAC -> буфер/ОУ LEFT  -> 1 кОм -> Turn handle Signal LEFT
GPIO26 DAC -> буфер/ОУ RIGHT -> 1 кОм -> Turn handle Signal RIGHT

GND аналоговой платы -----------------> Turn handle GND LEFT
GND аналоговой платы -----------------> Turn handle GND RIGHT
```

Операционный усилитель:

- rail-to-rail вход/выход;
- питание 5 В;
- два канала;
- коэффициент усиления около 1,27 для получения 4,2 В из 3,3 В;
- обязательная проверка реального минимального и максимального напряжения контроллера.

Перед подключением к силовому контроллеру проверить мультиметром:

```text
DISARMED -> безопасное состояние
IDLE     -> около требуемого нуля контроллера
минимальная команда -> плавное увеличение
максимальная тестовая команда -> не выше установленного лимита
```

Если контроллер считает 0 В неисправностью ручки газа, нельзя использовать 0 В как нормальную остановку при разрешённом контроллере. В прошивке при разрешённом приводе используется `DAC_IDLE`, а `DAC_DISARMED=0` только при блокировке контроллера.

## 9. Тормоз Low brake

Для каждого контроллера используется отдельный вход:

```text
GPIO18 -> Low brake LEFT
GPIO19 -> Low brake RIGHT
```

Подключать через открытый коллектор или оптопару:

```text
ESP32 GPIO18 -> резистор -> оптопара/транзистор -> Low brake LEFT
ESP32 GPIO19 -> резистор -> оптопара/транзистор -> Low brake RIGHT
```

Типичная логика `Low brake` — замыкание сигнального входа на GND контроллера, но это необходимо подтвердить измерением именно на вашем контроллере.

В прошивке полярность интерфейсной платы задаётся:

```cpp
constexpr bool BRAKE_ACTIVE_HIGH = true;
```

Это уровень на низковольтной стороне интерфейсной платы, а не прямой уровень неизвестного провода контроллера.

## 10. Реверс

```text
GPIO16 -> Reverse LEFT
GPIO17 -> Reverse RIGHT
```

Выходы подключаются через оптопары или реле. Перед подключением проверить, действительно ли найденный разъём является рабочим `Reverse`, а не проводами обучения.

Белые провода самообучения нельзя использовать как рабочий реверс.

При смене направления прошивка выполняет:

```text
1. Газ в ноль.
2. Тормоз включён.
3. Пауза REVERSE_BRAKE_MS.
4. Переключение Reverse.
5. Пауза REVERSE_SETTLE_MS.
6. Отпускание тормоза.
7. Плавный набор газа.
```

Настройки:

```cpp
constexpr uint32_t REVERSE_BRAKE_MS = 700;
constexpr uint32_t REVERSE_SETTLE_MS = 300;
constexpr bool REVERSE_SUPPORTED = true;
```

Если отдельного рабочего входа реверса нет:

```cpp
constexpr bool REVERSE_SUPPORTED = false;
```

Не переключать силовые фазные провода реле во время работы.

## 11. Разрешение/включение контроллеров

```text
GPIO21 -> Enable LEFT
GPIO22 -> Enable RIGHT
```

Эти GPIO не подключаются непосредственно к тонкому проводу замка/включения контроллера.

Возможная схема:

```text
GPIO21 -> транзистор -> реле LEFT  -> цепь Ignition/Lock LEFT
GPIO22 -> транзистор -> реле RIGHT -> цепь Ignition/Lock RIGHT
```

Если на цепи Ignition/Lock присутствует напряжение аккумулятора, использовать контакты реле или интерфейс, рассчитанный на соответствующее напряжение.

Настройка логики низковольтного интерфейса:

```cpp
constexpr bool ENABLE_ACTIVE_HIGH = true;
```

## 12. Датчики Холла и скорость

### 12.1. Разъём Hall двигателя

Типичный пятижильный жгут:

```text
красный  -> +5 В
чёрный   -> GND
жёлтый   -> Hall A
зелёный  -> Hall B
синий    -> Hall C
```

Цвета обязательно проверить.

Штатный Hall-разъём остаётся соединённым между двигателем и контроллером. ESP32 подключается параллельно только к одному сигнальному каналу каждого двигателя.

```text
Hall A LEFT  -> согласование 5 → 3,3 В -> GPIO34
Hall A RIGHT -> согласование 5 → 3,3 В -> GPIO35
```

### 12.2. Простой делитель для стендового теста

```text
Hall 5 В -------- 10 кОм ----+---- GPIO34/35
                             |
                            18 кОм
                             |
Hall GND --------------------+---- ESP32 GND
```

При 5 В на входе ESP32 получит около 3,2 В.

Для рабочей машины предпочтительнее:

```text
Hall -> высокоомный вход -> триггер Шмитта 3,3 В -> ESP32
```

или гальванически развязанный импульсный вход.

### 12.3. Определение направления

Один Hall-канал показывает количество импульсов, но не определяет направление самостоятельно. Прошивка присваивает импульсам знак по текущей команде реверса.

Это достаточно для движения под управлением ESP32, но не определяет направление свободного прокручивания выключенного мотора. Для полной квадратурной обратной связи потребуется два Hall-канала на двигатель.

## 13. Аварийная петля

Программный аварийный вход:

```text
GPIO32 ---- нормально замкнутая кнопка NC ---- GND
```

Состояния:

```text
LOW  -> петля исправна
HIGH -> кнопка нажата, разъём снят или провод оборван
```

При HIGH прошивка:

- обнуляет команды;
- включает тормоза;
- снимает Enable;
- запрещает повторное включение.

Аппаратная аварийная цепь должна дополнительно размыкать питание катушки главного силового контактора. Нельзя полагаться только на ESP32 и программный код.

## 14. Связь ESP32 с Raspberry Pi

Связь выполняется по USB Serial:

```text
Raspberry Pi USB-A -> USB ESP32 DevKit
```

Параметры:

```text
115200 бод
ASCII-строки
окончание \n
XOR-контрольная сумма *HH
```

На Raspberry Pi ESP32 обычно появляется как:

```text
/dev/ttyUSB0
```

или:

```text
/dev/ttyACM0
```

Проверка:

```bash
ls -l /dev/ttyUSB* /dev/ttyACM* 2>/dev/null
dmesg | tail -n 30
```

Рекомендуется создать постоянное имя:

```text
/dev/esp32drive
```

и указать его в:

```text
config/esp32_drive.yaml
```

### 14.1. Что передаёт Raspberry Pi

```text
DRV,sequence,left,right*HH
ARM,sequence,1*HH
ARM,sequence,0*HH
STOP,sequence*HH
PING,sequence*HH
```

Команды гусениц имеют диапазон:

```text
-1000 ... 0 ... +1000
```

### 14.2. Что передаёт ESP32

```text
TEL,millis,armed,estop_ok,targetL,targetR,actualL,actualR,
ticksL,ticksR,ppsL,ppsR,watchdog,mode,
rc_ch1_us,rc_ch2_us,rc_mode_us,rc_arm_us,rc_valid,rc_input_mode*HH
```

Значения режима:

```text
RC
SAFE
ROS
```

Значения способа обработки пульта:

```text
BOAT_MIX  -> CH1 и CH2 уже являются командами гусениц
ESP32_MIX -> ESP32 смешивает газ и руление сама
```

## 15. Логика приоритетов

### Ручной режим

```text
MC7 -> MC8RE -> ESP32 -> силовые контроллеры
```

Raspberry Pi не влияет на движение, но продолжает получать Hall и телеметрию.

### Автономный режим

```text
Nav2 -> /cmd_vel -> Raspberry Pi -> USB -> ESP32 -> контроллеры
```

Для движения одновременно требуются:

```text
CH5 = ROS
CH6 = ARM ON после предварительного OFF
ROS service /drive/arm = true
аварийная петля исправна
USB-команды поступают без тайм-аута
```

### SAFE

При CH5 в среднем положении:

```text
газ = 0
тормоз = ON
enable = OFF
```

### Потеря связи

- потеря RC PWM переводит систему в безопасное состояние;
- потеря USB-команд в режиме ROS срабатывает через watchdog;
- разрыв аварийной петли блокирует привод;
- переключение RC/SAFE/ROS всегда сначала останавливает машину.

## 17. Порядок первого запуска

### Этап 1. Только ESP32

Подключить:

- ESP32 по USB;
- перемычку GPIO32–GND вместо аварийной кнопки;
- ничего не подключать к силовым контроллерам.

Проверить загрузочную строку в Serial Monitor.

### Этап 2. Приёмник MC8RE

Подключить:

- питание 5 В;
- общую землю;
- CH1, CH2, CH5, CH6.

Проверить телеметрию:

```text
центр CH1/CH2 около 1500 мкс
CH5 изменяется примерно 1000/1500/2000
CH6 изменяется примерно 1000/2000
rc_valid = 1
```

Выключить пульт и убедиться, что система переходит в SAFE/блокировку.

### Этап 3. Проверка выходов без контроллеров

Мультиметром проверить:

- GPIO25 и GPIO26/DAC;
- выходы интерфейсной платы Brake;
- выходы Reverse;
- реле/ключи Enable.

В нейтрали и SAFE не должно возникать команды движения.

### Этап 4. Один силовой контроллер

1. Вывесить гусеницу.
2. Подключить только один контроллер.
3. Оставить `DAC_MAX_TEST = 220`.
4. Проверить Enable.
5. Проверить тормоз.
6. Подать минимальную команду вперёд.
7. Остановить.
8. Только после полной остановки проверить реверс.
9. Выключить пульт — привод должен отключиться.
10. Разомкнуть GPIO32 — привод должен отключиться.

### Этап 5. Второй контроллер

Повторить тест для правой гусеницы. Только после этого подключать оба двигателя одновременно.

### Этап 6. Hall

Подключить Hall-сигналы через согласователи. Проверить изменение:

```text
ticksL
ticksR
ppsL
ppsR
```

### Этап 7. Raspberry Pi

Установить:

```bash
sudo apt install -y python3-serial
```

Настроить:

```yaml
esp32_track_bridge_node:
  ros__parameters:
    dry_run: false
    serial_port: /dev/esp32drive
    baud_rate: 115200
    auto_arm: false
```

Запустить:

```bash
ros2 launch robotlidar tractor_sensors.launch.py \
  serial_port:=/dev/ldlidar \
  use_esp32_drive:=true
```

Проверить:

```bash
ros2 topic echo /drive/esp32_status
ros2 topic echo /drive/hall_ticks
ros2 topic echo /wheel/odom
```

## 18. Калибровка Hall-одометрии

В `config/esp32_drive.yaml` заданы временные значения:

```yaml
pulses_per_motor_revolution: 6.0
gear_ratio: 30.0
drive_sprocket_circumference_m: 0.40
track_width_m: 0.60
```

Для калибровки:

1. Сделать метку на ведущей звезде.
2. Запомнить начальное значение `/drive/hall_ticks`.
3. Выполнить ровно 10 оборотов звезды.
4. Запомнить конечное значение.
5. Разделить разницу тиков на 10.
6. Измерить фактическое перемещение гусеницы за один оборот звезды.
7. Внести значения в YAML.

Если измеряются импульсы уже на выходной звезде, удобно использовать:

```yaml
pulses_per_motor_revolution: ФАКТИЧЕСКИЕ_ИМПУЛЬСЫ_НА_ОБОРОТ_ЗВЕЗДЫ
gear_ratio: 1.0
drive_sprocket_circumference_m: ФАКТИЧЕСКОЕ_ПЕРЕМЕЩЕНИЕ_ЗА_ОБОРОТ
```

## 20. Краткая таблица всех соединений

```text
MC8RE CH1 S  -> 1 кОм -> ESP32 GPIO27

ESP32 GPIO32 -> NC аварийная кнопка -> GND

Raspberry Pi USB -> USB ESP32
```

## 21. Что пока не подключать

До точного определения назначения оставить неподключёнными:

- `Three speed`;
- `Burglar alarm`;
- неизвестные одиночные провода;
- белые провода самообучения после завершения обучения;
- High brake, если используется Low brake;
- неизвестный Reverse до проверки мультиметром;
- +5 В разъёма Turn handle к ESP32;
- любые силовые фазные провода к интерфейсной плате ESP32.

Сначала проверяется низковольтная логика, затем один привод, затем второй привод, и только после этого автономное управление ROS 2.
