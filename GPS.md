# GPS-помощь RobotLidar

GPS в RobotLidar является **необязательным дополнительным источником**. Основная
навигация остаётся на LiDAR, датчиках Холла и MPU6500. Потеря спутников,
отключение антенны или отсутствие GPS в помещении не должны останавливать
трактор.

## Подключение NEO-6M к Raspberry Pi 4

```text
NEO-6M                 Raspberry Pi 4
------------------------------------------------
TXD  ----------------> BCM GPIO15 / RXD / physical pin 10
RXD  <---------------- BCM GPIO14 / TXD / physical pin 8   (необязательно)
PPS  ----------------> BCM GPIO18 / physical pin 12        (необязательно)
GND  ----------------- GND / physical pin 6
VCC  ----------------- питание конкретной платы GPS
```

UART Raspberry Pi имеет уровни 3,3 В. Системная консоль должна быть удалена из
`/boot/firmware/cmdline.txt`, но сам UART должен оставаться включённым:

```text
enable_uart=1
```

Проверенная скорость модуля — `9600` бод.

## ROS 2-топики

`gps_node` публикует:

```text
/gps/fix           sensor_msgs/NavSatFix
/gps/status        std_msgs/String, JSON диагностика
/gps/odom          nav_msgs/Odometry, только качественные и согласованные фиксы
/gps/assist_ready  std_msgs/Bool
```

Сервис сброса локальной GPS-привязки:

```bash
ros2 service call /gps/reset_assist std_srvs/srv/Trigger "{}"
```

## Как GPS помогает одометрии

Обычный GPS сообщает координаты относительно сторон света, а локальная система
`odom` начинается в произвольном направлении трактора. Поэтому GPS нельзя сразу
подмешивать в локальный EKF.

`gps_node` выполняет следующую последовательность:

1. ждёт качественный фикс;
2. запоминает первую GPS-координату и текущую позицию `/wheel/odom`;
3. ждёт движения минимум на заданное расстояние либо достоверного курса RMC;
4. вычисляет поворот между GPS ENU и локальной системой `odom`;
5. публикует `/gps/odom` с большой ковариацией;
6. при потере фикса прекращает GPS-измерения, не затрагивая Холлы и IMU.

По умолчанию принимаются только фиксы при условиях:

```text
минимум спутников: 4
максимальный HDOP: 4.0
максимальный скачок: 15 м плюс допустимое движение за время между фиксами
минимальный sigma GPS для EKF: 2.5 м
```

Таким образом, старый NEO-6M не перетягивает на себя локальную навигацию и лишь
медленно ограничивает накопление ошибки на открытом пространстве.

## Запуск

GPS стартует вместе с общим запуском датчиков:

```bash
ros2 launch robotlidar tractor_sensors.launch.py \
  gps_port:=/dev/ttyS0
```

Отключить GPS для конкретного запуска:

```bash
ros2 launch robotlidar tractor_sensors.launch.py start_gps:=false
```

Проверка:

```bash
ros2 topic echo /gps/status
ros2 topic echo /gps/fix --once
ros2 topic echo /gps/assist_ready
ros2 topic hz /gps/odom
```

При отсутствии фикса `/gps/fix` может содержать статус `NO_FIX`, а `/gps/odom`
не публикуется.

## Веб-интерфейс

Главная панель и страница `/radar` показывают:

- наличие UART-данных GPS;
- наличие фикса;
- широту и долготу;
- число используемых и видимых спутников;
- HDOP;
- скорость и курс GPS;
- состояние согласования с `odom`;
- активность помощи EKF;
- причину отклонения плохого измерения.

HTTP API:

```text
GET  /api/gps
POST /api/gps/reset-assist
```

## Запись маршрута

`route_recorder_node` сохраняет GPS-координаты рядом с точками маршрута, когда
фикс действителен и не старше трёх секунд. Старые маршруты формата 1 продолжают
воспроизводиться. Новый файл имеет `format_version: 2` и содержит поля:

```yaml
gps_point_count: 123
gps_origin:
  latitude: 55.0
  longitude: 37.0
points:
  - x: 0.0
    y: 0.0
    yaw: 0.0
    gps:
      latitude: 55.0
      longitude: 37.0
      altitude_m: 180.0
      horizontal_sigma_m: 3.5
```

## PPS

PPS не требуется для работы навигации и GPS-помощи. Его можно оставить
подключённым к GPIO18 и использовать позже для синхронизации времени. Отсутствие
PPS никак не влияет на `/gps/fix` и `/gps/odom`.
